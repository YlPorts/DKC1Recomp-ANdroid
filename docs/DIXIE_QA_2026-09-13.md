# Dixie Kong Country QA - September 13, 2026

Historical report: the map failure below was subsequently diagnosed and fixed.
See [September 14 map fix and save refresh](DIXIE_MAP_FIX_2026-09-14.md) for
the current result; this report retains the original failure evidence.

## Result and scope

Dixie replaces DK and looks coherent in the inspected Jungle Hijinxs gameplay:
idle, walking, jumping, ponytail spin, ground attack, barrel carry/throw and
character swaps. Diddy remains available. This is a playable experimental
Windows variant, **not a fully working or full-game-certified release**.
Fresh map screens still contain conspicuous garbage sprites. No release was
published or archive replaced during this QA.

All evidence below is under the private, ignored directory
`build/dixie-qa-20260913/`. ROMs, generated sources, snapshots and captures stay
out of commits. The baseline dirty diff/status and existing engine-submodule
diff were preserved before changes. The existing variant-only engine DMA
workaround was not edited.

## Repairs made during QA

1. **ROM selection and restart routing (host integration).** Menu restarts lost
   the selected clean-ROM path, executable paths were not safely quoted, and
   the SDL variant returned to the debugger filename. Remember the resolved
   ROM, use an explicit CreateProcess executable, preserve quoted arguments,
   and return to the matching SDL/debugger sibling. Resolve a cached/picked
   ROM before the second no-argument startup handoff. Explicit menu changes
   override inherited `DKC1_DIXIE`; failed menu launches restore the previous
   preference. Initialize status text on all handoff paths. Actual stock ->
   Dixie -> stock menu restarts were exercised with a ROM path containing
   spaces. Switching restarts the game; session-state transfer is not promised.
2. **Windows build integration.** Add default-off CMake option
   `DKC1_BUILD_DIXIE_VARIANT` to build the SDL Dixie sibling from the separate
   private generated tree. Correct platform self-test menu arguments and its
   checkmark assertion; remove an unused menu allocation that broke `/WX`.
3. **ROM identity isolation.** The stock runtime no longer accepts the 6 MiB
   mod ROM against stock generated code. The separate Dixie loader accepts
   only its pinned image or synthesizes that exact image from the verified
   clean ROM. Zero-initialize the expansion before applying IPS records.
   Clean versus already-patched 600-frame runs have identical image, guest
   memory and audio hashes; stock rejects the patched image with exit code 2.
4. **SDL startup-route timing.** `RunStartupScript` ran CPU frames without the
   normal drawing step. That step also executes HDMA and the VBlank OAM-port
   reload. Fresh startup therefore corrupted sprites in both stock and Dixie,
   despite equal WRAM/VRAM/CGRAM and OAM-shadow hashes. Initialize the offscreen
   drawing target and call `Dkc1DrawPpuFrame` once per successful startup frame.
   This changes only the explicitly requested startup route. No PPU repair,
   sprite filtering, guest-memory rewrite or widescreen policy was added.

The startup failure was visible at the first interactive frame following the

## Remaining failure: map sprite corruption

Fresh controller-only boot produces garbage sprite clusters on both the Kongo
Jungle map and Jungle entrance map. A fresh map transition first publishes the
tracked Jungle cluster in PPU OAM at absolute frame **5728**; screenshots around
5700 also show earlier corruption on the preceding Kongo map, so 5728 is not
claimed as the first bad frame of the entire run. Re-entry after death shows
the map problem again. It survives the SDL startup correction and also occurs
in headless runs that execute the complete render/VBlank step every frame.

`map-first-bad/` captures every frame from 5700 through 5749 plus raw memories
and paired OAM evidence. At the final map frame the shadow and PPU OAM agree;
this is separate from the startup helper's OAM-port timing defect. The saved
map-state hash is
`4c34144e907695675dc1008733dc49ef01fda0b5c2930f6c741ce1d237e4ed81`.
Its framebuffer hash is
`3ad04f653c435ebe20316248b1531226315a77eafa68a47039bbcd9c1aaeec91`.
The direct input reproduction is the first 5750 frames of
`recipes/dixie-jungle-startup.dks` from clean boot with the Dixie headless host.

The responsible mod animation/graphics-data path is **not yet proven**. This
checkout currently has `reference/README.md` but lacks the documented byte-exact
disassembly/atlas library. Earlier symbolic DMA findings remain historical
leads. No broad sprite suppression or serialized-state rewrite was attempted.
Recorded as `dixie-map-sprite-corruption` in `KNOWN_ISSUES.json`.
